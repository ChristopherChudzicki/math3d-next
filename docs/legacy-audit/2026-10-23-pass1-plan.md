# Legacy audit, pass 1: implementation plan

The spec is [2026-10-23-pass1-spec.md](2026-10-23-pass1-spec.md). The math3d-next branch is `legacy-audit/pass1`; the math3d-react branch is `legacy-audit/rehydrate`.

## Steps

1. **math3d-react: defaults export + rehydrate audit** (`client/src/legacyAudit/`).
   - `rehydrate.audit.js` writes `defaults.json` when `LEGACY_AUDIT_DEFAULTS_OUT` is set.
   - It writes `rehydrated.jsonl` when `LEGACY_AUDIT_IN`/`LEGACY_AUDIT_OUT` are set.
   - Add a README and a CLAUDE.md note.
   - Copy `defaults.json` into math3d-next as the test fixture `webserver/scenes/legacy_audit/fixtures/react_defaults.json`.
2. **Translator refactor** (`legacy_scene_utils/`).
   - Add `translate_legacy_scene(dehydrated) -> TranslatedScene` and `set_defaults_dict`.
   - `migrate_scene` keeps its behavior.
   - Add a test that the pure result equals what `migrate_scene` persists.
3. **`export_legacy_audit`** (`scenes/management/commands/`). Use `translate_legacy_scene` + `validate_math_items`, iterate with `.iterator()`, and write JSONL in id order.
4. **Expected-translation table** (`scenes/legacy_audit/expected.py`).
   - Written by a separate agent that must not read `legacy_scene_utils/`.
   - Add completeness tests against the fixture and the Pydantic models.
5. **Comparison engine + command**:
   - `scenes/legacy_audit/normalize.py`, `compare.py`, `report.py`;
   - `audit_legacy_migration`;
   - tests for each outcome class and for the mutation test.
6. **Run** export → Jest → audit on the snapshot. Hand-check the calibration set and write `docs/legacy-audit/reports/2026-10-23-pass1.md`. File a witan task for each confirmed cluster.

Steps 2–3 and step 4 run in parallel once the step 1 fixture exists.

## Interface between the table (step 4) and the engine (step 5)

```python
# scenes/legacy_audit/expected.py
Severity = Literal["render", "editor", "none"]


@dataclass(frozen=True)
class NeedsEval:
    reason: str


@dataclass(frozen=True)
class Expectation:
    path: str  # dotted path under the migrated item's "properties", list indices as ints: "domain.items.0.rhs"
    value: Any | NeedsEval  # the math3d-next value math3d-react's rendering implies
    severity: Severity
    source: str  # legacy property name(s), or "constant"


@dataclass(frozen=True)
class Context:
    item_id: str
    axes: dict[
        str, dict
    ]  # rehydrated "axis-x"/"axis-y"/"axis-z" items (raw legacy values)
    slider_values: dict[str, Any]


# For each legacy type: legacy property -> "target path(s) / transform note" or "dropped: <reason>".
# Each entry cites the math3d-react code it reproduces and the math3d-next code that consumes it.
COVERAGE: dict[str, dict[str, str]]

# For each legacy type: the full expectation list for one rehydrated item. It must cover
# EVERY leaf field of the math3d-next Pydantic properties model (constants included).
EXPECTATIONS: dict[str, Callable[[dict, Context], list[Expectation]]]

LEGACY_TYPE_TO_NEXT_TYPE: dict[
    str, str
]  # identity today; explicit so a rename is visible
```

The engine compares each `Expectation` with the value at `path` in the migrated item. Unknown legacy properties are any key of the rehydrated item that is not in the fixture's `defaultSettings` for that type and is not `type`. The engine finds these itself; the table doesn't list them.
